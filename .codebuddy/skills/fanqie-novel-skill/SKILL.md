# 番茄小说写作 Skill（Fanqie Novel Skill）

版本：**2.0.1** | 作者：**Jayce**

**专为番茄小说平台打造的长篇网文写作系统。**

---

## 核心定位

本 Skill 解决**八个**核心问题：

1. **长篇不跑偏**：通过 Truth Files 系统维护世界观、角色、伏笔、状态
2. **番茄能签约**：内置番茄平台规则、商业审查、付费转化检查
3. **AI没味道**：智能 AI 去味检查（替换而非删除），避免被平台限流
4. **会话连续性**：通过 handoff_current.md 实现跨会话无缝衔接
5. **规划能落地**：进度追踪面板，实时监控字数/章节偏离
6. **战斗有张力**：战斗场景专项审计，杜绝"话疗"解决BOSS
7. **对话不注水**：对话占比监控，防止全章变成聊天记录
8. **节奏不崩塌**：高潮密度追踪，防止后期注水和循环重复

---

## 核心工作流

```
init -> write-next -> draft -> ai-detox -> audit -> revise -> extract-state -> state-update -> handoff-update
```

### 写前（强制5项）：
1. 读取 current_state.md -> 确认地点/时间/状态
2. 读取 outline.md -> 确认本章目标、字数、是否高潮章
3. 读取 pending_hooks.md -> 确认待处理伏笔
4. 检查 battle-scene-guide.md -> 如是战斗章，加载战斗描写清单
5. 检查 dialogue-monitor.md -> 确认当前对话占比趋势

### 写后（强制8项 -- 最小审计集）：
1. 字数检查（2000-2500字）
2. AI去味（智能替换，非机械删除）
3. 因果链检查（维度29，无跳脱）
4. 行为-规则一致性检查（维度28）
5. 时间线检查（无黑洞）
6. 战斗场景检查（维度30，高潮章必查）
7. 对话占比检查（维度31，上限40%）
8. 话疗模式检查（维度32，BOSS禁止被说服）

### 状态更新（强制）：
- current_state.md
- pending_hooks.md
- handoff_current.md
- progress_tracker.md
- pattern-detection.md

## 最小审计集（8项强制检查）

每章写完后**必须执行**以下8项检查，不可跳过：

### 检查1：字数检查

目标：2000-2500字（可根据book_rules.md调整）
- ✅ 通过：2000 ≤ 字数 ≤ 2500
- ⚠️ 不足：字数 < 2000 → 必须扩充
- ⚠️ 超标：字数 > 3000 → 建议拆分

### 检查2：AI去味检查（智能替换）

步骤：
1. 搜索禁用词（不禁、竟然、居然、仿佛、宛如、深邃、命运、瞳孔收缩、嘴角上扬）
2. 分析语境（是否在对话中？是否必要？）
3. 智能替换（见 references/ai-detox-guide.md 替换表）
4. 语义完整性验证
5. 记录替换结果

### 检查3：因果链检查（维度29）

检查项：
- 每个场景转换是否有因果连接？
- 是否有"突然""然后"连接无因果的事件？
- 主角行为是否有动机支撑？
- 新角色出场是否有前置铺垫？

### 检查4：行为-规则一致性检查（维度28）

检查项：
- 本章是否声明了规则？
- 规则说X，主角是否做了非X？
- 如果做了非X，是否有明确解释？
- 其他角色行为是否符合规则？

### 检查5：时间线检查

检查项：
- 时间跳跃是否交代了中间发生了什么？
- 是否存在"时间黑洞"（跳跃>1小时无交代）？

### 检查6：战斗场景检查（维度30）

触发条件：
- 章节标题含"战斗/决战/对抗/最终/击杀"等关键词
- outline.md 标记为"高潮章"
- 本章出现BOSS级敌人

检查项：
1. 是否有实质性攻击/防御动作？（至少3次）
2. 是否通过"说服/理解/感化"解决冲突？-> 🔴 禁止！
3. 战斗意象是否重复？
4. 是否有战术博弈？（而非纯力量对轰）
5. 是否有代价/牺牲？

评级标准：
- ✅ 优秀：有战术、有代价、意象丰富、攻击动作≥5次
- ⚠️ 及格：有战斗但模式化，攻击动作3-4次
- 🔴 不合格：无战斗或"话疗"解决BOSS

### 检查7：对话占比检查（维度31）

计算方法：
- 对话行数 = 统计引号内内容行数
- 总行数 = 章节总行数（排除空行）
- 对话占比 = 对话行数 / 总行数

标准：
- ✅ 优秀：≤ 25%
- ✅ 良好：26-35%
- ⚠️ 偏高：36-40%
- 🔴 超标：> 40%（必须压缩对话）

趋势监控：连续3章占比上升 -> 预警；占比>50% -> 立即报警

### 检查8：话疗模式检查（维度32）

检测关键词："我理解你"、"说服"/"感化"/"唤醒"、"不是消灭，是救赎"、"融入"/"共存"/"和解"

检查规则：
- 普通敌人：可通过对话解决（限1次/卷）
- 精英敌人：对话解决需铺垫3章+
- BOSS级敌人：禁止通过对话解决！必须战斗！

### 检查9：循环模式检查（维度33，每5章执行）

检测模式：
1. 检查最近5章的章节结构是否高度相似
2. 检查"遇到新敌人→发现苦衷→对话解决→获得力量"模式
3. 检查高潮章是否真的有高潮

预警规则：
- 同模式出现2次 -> WARN 提醒
- 同模式出现3次+ -> FAIL 报警，要求变化

## 会话连续性工作流

### 新会话启动流程

1. 用户请求继续写作
2. AI请求加载 handoff_current.md
3. 用户提供文件内容（或AI从项目文件夹读取）
4. AI确认加载成功，报告当前进度
5. 继续写作或审计

### 会话交接确认格式

```
已加载 handoff_current.md，当前进度：ch{{N}}，下一章：ch{{N+1}}。
主角当前在[地点]，持有[物品]，待处理伏笔[X个]。
总进度：{{actual}}字/{{target}}字（{{percent}}%）。
对话占比趋势：{{trend}}。上次高潮章：ch{{last_climax}}。
```

## 进度追踪面板

### 节奏质量评估

```markdown
高潮密度：高潮章数量 / 总章数
标准：>= 15%（每7章至少1个高潮）

冲突强度趋势：
统计每章冲突解决方式
战斗解决占比应 >= 对话解决占比

节奏曲线：
绘制章节质量曲线
检测是否"前高后低"崩塌
```
